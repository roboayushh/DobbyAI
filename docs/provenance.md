# Provenance and licenses

## What ships

| Artifact | Generated by | Contents |
|---|---|---|
| `requirements.lock` | `uv pip compile --generate-hashes` | Every host dependency, pinned with a SHA-256 hash. `make setup` installs with `pip --require-hashes`. |
| `runtime/python/requirements.lock` | reviewed by hand | Hash-pinned tooling baked into the sandbox image: pytest, pluggy, iniconfig, packaging. |
| `runtime/python/Dockerfile` | — | Base image `python:3.12-slim`, pinned by multi-arch index digest (`sha256:f77ac9e4…`). |
| `config/runtime.lock.json` | `harness sandbox build` | The content-addressed image ID actually used on this machine, plus its labels. |
| `licenses/sbom.cdx.json` | `make sbom` | CycloneDX SBOM of the host and runtime components (36 components) with versions, hashes, and licenses. |
| `licenses/THIRD_PARTY_NOTICES.md` | `make sbom` | Human-readable license table, read from each distribution's own metadata. |
| `config/plugins/builtin_release_v1.lock.json` | `make plugins-lock` | SHA-256 of every plugin module that may load. |

All third-party licenses are permissive: MIT, BSD-2/3-Clause, Apache-2.0, ISC, PSF,
and MPL-2.0 (certifi, unmodified). None of them imposes copyleft obligations on the
harness. Redistributing the harness requires keeping `THIRD_PARTY_NOTICES.md` and the
upstream license texts that come with each wheel.

## Copied code

No third-party source code is copied into `src/`. The in-container tool library
(`src/harness/worker/`), the egress proxy, the patch adapter, and the development
bridge (`scripts/claude_openai_bridge.py`) are original to this repository.
Tree-sitter grammars are used as unmodified wheels (`tree-sitter-python`,
`tree-sitter-javascript`).

## Per-run provenance

Every run records a reproducibility manifest (`h_reproducibility_manifests`, also
exported as `bundle/evidence/provenance.json`) that binds:

- the harness version, source commit (with `-dirty` when uncommitted), and build ID;
- the evaluator adapter name, version, and content hash;
- the model: provider endpoint, model ID, adapter version, profile fingerprint, and
  sampling settings;
- the runtime image digest, architecture, and dependency-lock hash;
- the source baseline commit and tree, and the candidate commit and tree;
- the verification contract, environment, and test-command set hashes;
- the plugin-set lock hash;
- the schema versions (request, result, event, database migration);
- the effective configuration hash.

`harness replay RUN_ID --mode audit` rechecks these against the stored artifacts.

## Development-time model

The harness was developed and tested end to end locally using Claude, through the
development bridge (`claude-bridge` profile). Those runs are labeled as development
evidence and never count as prescribed-model evidence. DeepSeek and Qwen are
supported through the same OpenAI-compatible adapter ([profiles.md](profiles.md)).
